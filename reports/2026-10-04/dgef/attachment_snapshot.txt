## 一、先斩一个最危险的前提：“一个都不许遗漏”不能作为事实承诺

“全球所有公开机构尽量无漏”可以成为**工程目标**。

但：

> **“所有秘密基地、没有网站的组织、未公开设施一个都不遗漏”在认识论上无法证明。**

因为真正未公开对象没有完整可验证分母；“没有查到”既不能证明不存在，也不能证明已经查全。

因此建议把最高目标改写成：

> **已知世界无静默漏项；未知世界有正式席位。**

即：

```text
VERIFIED
OBSERVED
INFERRED
CLAIMED
UNKNOWN
RESTRICTED_NOT_INGESTED
```

最后两个状态与前四个一样，是合法结果。

对于所谓“秘密基地”，建议只建立：

```text
PUBLICLY_ACKNOWLEDGED_FACILITY
PUBLIC_RESEARCH_FACILITY
PUBLIC_DEFENCE_FACILITY
PUBLIC_SPACE_FACILITY
```

并允许：

```text
UNKNOWN_FACILITY_EXISTS
location = NULL
```

而不是搜集、推断或聚合未公开军事／安全设施的精确坐标。

这不是退化，而是**史家不妄书、名家先正名、墨家必验、兵家慎泄机**。

# 二、真正应统一的不是一套经纬度，而是“五种坐标”

建议把现有 DAQIN-UCS 与 DUECG 正式分工。

**DAQIN-UCS = 技术／组件坐标。**

继续保留现有：

```text
DOM / LAYER / CLASS / NAME
VERSION / ARCH / LOCUS / ROLE
```

它适合 Windows、Linux、GPU、数据库、AI、软件、硬件、云、算法。

**DUECG = 天下万物实体坐标。**

建议成为人物、企业、政府、研究所、天体、航天器、城市、虚拟世界的母坐标：

```text
DUECG::<WORLD_DOMAIN>/<ENTITY_TYPE>/<ENTITY_ID>
      @<VALID_TIME>#<SPATIAL_FRAME>
```

再增加三个**属性而非主键**：

```text
JURISDICTION
EVIDENCE_STATE
SENSITIVITY_CLASS
```

这样同一个 SpaceX 不会因为换 CEO、地址或产品而换 `ENTITY_ID`；同一颗小行星也不会因为新轨道解出来就变成另一个实体。

# 三、空间必须分七域，千万不要拿 WGS84 统治银河系

建议新增 `cosmic_domain`，而不是在 CSV 加更多 longitude/latitude 列：

| 宇域 | 正确坐标体系 |
|---|---|
| `EARTH_SURFACE` | WGS84／ITRF／EPSG |
| `EARTH_ORBIT` | GCRS／ITRF／TEME 等＋epoch |
| `SOLAR_SYSTEM` | ICRS／BCRS／JPL SPICE frame |
| `PLANETARY_SURFACE` | IAU body-fixed frame |
| `GALACTIC` | ICRS＋Galactic／Galactocentric |
| `EXTRAGALACTIC` | ICRS＋redshift／distance |
| `VIRTUAL_SIM` | simulator-local frame＋transform |

NASA 的 SPICE 本来就是为这种问题而设计：它管理惯性坐标、天体固定坐标、航天器坐标以及坐标之间随时间变化的转换。[naif.jpl.nasa.gov](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/FORTRAN/req/frames.html?utm_source=chatgpt.com)

所以任何宇航／天体记录至少应有：

```text
spatial_frame
frame_center
epoch
time_scale
x/y/z
vx/vy/vz
position_uncertainty
source_solution
```

没有 `frame + epoch + time_scale` 的“宇宙坐标”，原则上不得进入正式模型。

# RedTeam

目前最大的红队攻击不是“漏了一家公司”，而是以下四种灾难：

**第一，实体爆炸。**  
同一个集团、品牌、法人、子公司、实验室、网站被算成五个主体。

**第二，坐标污染。**  
经纬度、轨道状态向量、RA/Dec、虚拟世界 XYZ 全塞进 longitude/latitude。

**第三，来源污染。**  
官网、论文、商业数据库、论坛、“野网”、传闻都变成同等级证据。

**第四，秘密设施幻觉。**  
模型看见卫星影像或论坛传闻后自行“确认秘密基地”。

最后一种必须直接冻结。

# Blindspot

还有三个目前尤其值得补：

**时间旅行问题。**公司、边界、职位、设施、轨道都会变，所以必须双时间：

```text
valid_time
transaction_time
```

**实体消歧问题。**同名公司、改名、并购、分拆比神经网络建模更早、更重要。

**数据许可问题。**可查询 ≠ 可批量下载 ≠ 可训练模型 ≠ 可重新发布。

所以 `registry_source` 应有：

```text
license
redistribution_allowed
ml_training_allowed
commercial_use_allowed
retention_rule
```

**G4 模型关**：最后才建立供 NN/GNN/Transformer 使用的 materialized feature views。

这样便可以做到：

> **表可以无限增加，核心主键永远不变；新世界、新公司、新天体、新模型出现，都无需重建整个数据库。**

### 此轮最重要的架构裁定

没有另起炉灶。原来的三大核心被完整保留并重新正名：

真正新增的是永久实体根号：

