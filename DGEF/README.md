# 大秦天下万物实体织网 · DGEF

**正名而后用数，有据而后立说。** 华夏古史、春秋战国诸子百家的表达用于组织知识与论证；下列工程术语均为当代设计，不冒称古籍原句，也不把文化身份当作技术效果证据。

这是一套已运行的数据底座：44 张 SQLite STRICT 表、10 个视图及44份CSV导出。已接入26个公开API／官网响应；其中36表有记录、8表明确空置。适用范围是全球与各宇域，不设用户国籍、居所或马来西亚默认过滤。`REAL-TWIN / HISTORY / SIM / FICTION` 保留项目四域；空间域另列11项，互不代替。

本轮公开入库明细：科研记录160、法人92、政府类型49、公开研究设施37、天体28、物理参数45、来源关系38；各表可能记录同一实体，不可相加为公司数。宇航计划、任务、资产、运载器及公开地面中心各2条。研究成果表仅保存JPL列出的文献引用，不冒充已核全文或完整篇名。完整逐表对账见 `../reports/2026-10-04/dgef/tables/coverage/表施工与数据覆盖对账.csv`。

数据库位于 `artifacts/dgef.sqlite`；各表CSV位于 `artifacts/tables/`。空领域表是已施工的结构，不表示对应对象不存在。附件每个明确命名的表均有实体表或兼容视图，测试会检查漏项。`space_object` 暂指宇航资产视图，天体另入 `registry_celestial_object`，避免混义。

CSV导出按九个用途目录分类，由`table_layout.py`统一决定位置，重建继续使用分类路径。全项目表文件现址与旧址见[分类总索引](../reports/2026-10-04/table_reclassification/README.md)；历史来源URI通过该映射定位，不改写历史原行。

## RedTeam／墨家验伪

防范合并品牌冒充法人、外部ID换版串号、轨道和地表坐标混用、引用次数冒充能力、虚构位置、UNKNOWN变0，以及未经许可直接训练。约束检查INSERT与UPDATE，不能只保护首次导入。未知或删隐位置不接受数值坐标、速度或geometry_ref。

## Critic／名家正名

附件“16表”标题与清单不符；前后世界域枚举冲突；所谓恒久主键只能在持久映射和备份仍在时维持。拆表本身不会自动加速：本版按粒度分职，建立外键索引，执行计划实测按国家取行政单位使用索引。未做亿级数据、GPU、GNN或Transformer性能实验，不能冠以天下顶尖。

`REAL-TWIN` 是父版合并域；是否真实观测还需证据状态和指标方法判定。当前模型视图仅演示必要闸门，未完成事实与数字孪生的全部语义隔离；上线训练前须补充现实性标签、特征合同、泄漏检查与审核机制。

## KillCritic／止讹闸

无效UUIDv7、孤儿外键、非法世界域、参考系／中心／单位不匹配、缺失历元、删隐记录带坐标均拒绝；来源许可UNKNOWN时不进入训练视图。导入源指纹改变则要求显式迁移，不覆盖已接受基线。全部写入都须由连接启用 `PRAGMA foreign_keys=ON`，文件持有人仍可以改数据库；这不是部署级访问控制。

## Blindspot／知未详

未公开机构没有可证完整分母；IAF缺席不证明无宇航业务；SIMBAD官方称其不是完整catalogue。数据可查询不等于可训练或可再发布，许可表以NULL保留未知。CSV空字段约定为SQL NULL，使用数值字段时不得转换成0。SQL原型未配置加密、身份认证、密钥管理、权限分层、审计服务器或灾备复制，不能称为军工／国安级系统。

## Blueprint／百表分职

`source → dataset → identity bridge → entity → typed domain → claim/evidence/observation → approved feature view`。

外部下載資料的精華採用另遵守[來源覆核合同](../V2.0.1/governance/source_review_contract.md)。LEI 身份、會計合併 RR 關係及 REPEX 例外分職；ISIC 分類節點、SDG 採集聯絡表及統計觀測不能混成法人明細。此輪僅强化合同與研究方法，未將下載資料寫入 `artifacts/dgef.sqlite`，亦未增加獲准訓練資料。

实体不因名字相似自动合籍，模型不拥有实体身份裁决权；预测不得倒写canonical事实。数据字典见 `contracts/data_dictionary.csv`，DDL见 `schema.sql`；领域表各守自身记录粒度。框架只接入公开非操作性设施资料，不推断未公开设施坐标或现实攻击路径。

## ActionPlan／施工与验收

1. 使用Python 3.10+及支持STRICT表、JSON函数的SQLite（本机3.53.1）；不需安装第三方包。
2. 运行 `python DGEF/fabric.py`，生成或增补数据库、各表CSV与build_report.json，保留已入库身份。联网取数用`fetch_public.py`，核验与入库用`ingest_public.py`；已下载快照默认复用，不将重跑当成实时刷新。
3. 运行 `python DGEF/test_fabric.py` 与 `python DGEF/test_public_ingestion.py`，分别验证结构、隔离库闸门与实际公开数据原行保全、响应指纹、法人字段、星历逐数回验。
4. 后续依据适配合同逐库接入，先核许可和发布版，再消歧；不能将接口状态写成已完成全量入库。
5. 生产前补增量迁移、权限、灾备、恢复演练、时间格式校验、关系跨域规则、模型现实性标签及规模实测。新增维度不改旧CSV粒度。

附注：当前数据字典的通用字段解释按所属表粒度约束；各行业指标尚未有指标专册，不能据字段名发明量纲或打分。春秋战国文献应单独记录篇名、版本、原文与释义；本轮没有伪造古籍引用。
