# 十项全能证据级数据平台蓝图

## 目标

本蓝图将本对话至今的公开平台研究、附件内容、现有 ODS 风控数据工程经验，以及地缘—军事—宇航—策略服务商业化方向，统一为一个可分层、可审计、可断网、可扩展的平台。

“十项全能”不表示一套系统包办所有事情，而表示十个能力域都具备统一的实体、时间、空间、证据、权限、版本和经济价值接口。

## 0. 不可违反的总原则

- 事实、推断、预测、建议、行动严格分层。
- 所有数据都有来源、许可、采集时间、有效时间、版本、质量和责任人。
- 不能证明的军事、情报、卫星控制系统内部细节标为 UNKNOWN。
- 冲突来源标为 CONFLICT，不强行选一个。
- 不因组件知名、厂商宣传或采购合同反推内部技术栈。
- 生产数据不进入未经批准的 AI 或第三方服务。
- 高影响决定必须有人审、可申诉、可回滚和可审计。
- 商业化只能使用公开、合法授权、可再分发或明确允许衍生产品的数据。
- 目标是提高证据质量和商业价值，而不是制造“天下全知”的假象。

## 1. 十项能力域

| 编号 | 能力域 | 核心对象 | 数据价值 | 业务价值 |
|---:|---|---|---|---|
| 1 | 数据接入与证据采集 | 文件、API、数据库、传感器、事件 | 获得可追溯原始事实 | 降低手工采集和来源不明风险 |
| 2 | 数据湖仓与数据库 | 表、文件、空间对象、时间序列 | 统一存储、版本、查询和恢复 | 降低重复建设和查询成本 |
| 3 | 数据质量与血缘 | 字段、主键、规则、作业、版本 | 识别重复、缺失、漂移、泄漏 | 防止错误数据进入决策 |
| 4 | 时空 GIS 与数字地球 | 地点、轨迹、栅格、影像、地形 | 连接“何时、何地、何物” | 支持空间风险和资产管理 |
| 5 | 实体、本体与知识图谱 | 人、组织、资产、供应商、事件 | 解决同名、关联、关系和语义 | 支持供应链穿透和调查 |
| 6 | 流式计算与事件处理 | 实时事件、日志、遥测、告警 | 低延迟发现和回放 | 缩短响应和预警时间 |
| 7 | 统计、量化、AI 与因果 | 特征、模型、干预、结果 | 预测、排序、解释和策略评估 | 止损、增效和政策/运营评估 |
| 8 | 宇航仿真与系统工程 | 轨道、覆盖、链路、任务、环境 | 计算物理约束和情景 | 商业航天设计与保险定价 |
| 9 | 安全、断网与韧性 | 身份、密钥、权限、备份、边缘 | 保密、完整性、可用性 | 满足私有化、主权和连续性要求 |
| 10 | 决策产品与商业化 | 报告、API、地图、工作流、SLA | 将分析转成客户可用产品 | 订阅、项目、API、维护和培训收入 |

## 2. 总体架构

```text
数据源与传感器
  ├─ 公开 OSINT：GDELT、ACLED、UCDP、政策、企业、贸易、招标
  ├─ 地球观测：Copernicus/Sentinel、商业影像、SAR、STAC
  ├─ 气象环境：Meteomatics、公开气象机构、再分析、模式输出
  ├─ 航运航空：合法授权 AIS、ADS-B、港口和机场数据
  ├─ 宇航：TLE/星历、SPICE、轨道、地面站、任务参数
  ├─ 内部业务：经批准脱敏的 ODS/DWD/DWS/ADS 数据
  └─ 设备与系统：日志、遥测、IoT、应用事件
             ↓
接入层：API / SFTP / 文件 / CDC / Kafka / 批处理
             ↓
证据层：原始不可变区 + SHA-256 + 许可 + 采集时间 + 版本
             ↓
湖仓层：对象存储 + Parquet/Iceberg + Arrow + Catalog
             ↓
数据库层：PostgreSQL/PostGIS + DuckDB + 时序库 + 搜索/图数据库
             ↓
计算层：SQL + Polars + Python/R + Spark/Flink + GIS/轨道引擎
             ↓
语义层：实体解析 + Ontology + Knowledge Graph + 指标字典
             ↓
模型层：规则 + 统计 + ML + 生存 + 因果 + 情景 + 仿真
             ↓
服务层：API + GIS + Cesium + Quarto + Dashboard + 工作流
             ↓
治理层：权限、加密、审计、模型注册、人工复核、回滚、商业计量
```

Apache Parquet 是开放的列式存储格式，适合分析型数据；Apache Arrow 提供语言无关的列式内存格式，二者配合可减少跨语言复制并提升向量化处理效率。 [web:150][web:151][web:152]

Apache Iceberg 可为大型分析表提供 ACID、schema evolution、time travel、快照、回滚和并发写入能力，适合作为跨 Spark、Flink、Trino、DuckDB/其他引擎的数据表治理层。 [web:168][web:172]

Kafka 的事件流模式支持从数据库、传感器、软件应用和云服务捕获事件，持久化、重放、实时处理并路由到多个目的地。 [web:165][web:171]

Kubernetes 适合负责容器化服务的部署、扩展、滚动升级、回滚和存储编排，但不应被误认为数据治理、权限治理或灾难恢复的完整替代品。 [web:173][web:175]

## 3. 数据资产全盘登记

平台不应宣称“所有数据都保存”，而应建立数据资产目录，并对未采集数据明确记录。

每个数据集至少登记：

- `asset_id`：稳定资产编号。
- `domain`：地缘、宇航、气象、供应链、业务、财务、合规等。
- `source`：来源机构、接口、文件、设备或表。
- `license`：版权、数据库权、API 条款、再分发限制。
- `collection_time`：实际采集时间。
- `valid_time`：事实适用时间。
- `version`：来源或内部版本。
- `schema_hash`：结构指纹。
- `content_hash`：内容或文件指纹。
- `spatial_reference`：CRS、坐标和精度。
- `quality`：缺失、重复、延迟、定位误差、实体误并率。
- `security_class`：公开、内部、受限、个人、高敏、出口管制关联。
- `retention`：保存期限和删除规则。
- `owner`：责任人和批准人。
- `downstream_use`：报表、模型、API、客户产品和决策用途。
- `known_limitations`：偏差、覆盖空洞、历史修订和供应商依赖。

## 4. 数据分层

| 层 | 内容 | 不可做的事 |
|---|---|---|
| RAW | 原始文件、原始 API 响应、原始事件 | 不覆盖、不偷偷清洗 |
| BRONZE | 类型化、解压、基础格式统一 | 不改变事实含义 |
| SILVER/DWD | 去重、主键、时间、坐标、实体标准化 | 不隐藏失败记录 |
| GOLD/DWS | 业务聚合、指标宽表、主题数据集 | 不将推断冒充原始事实 |
| SEMANTIC | 实体、关系、本体、指标和动作 | 每个关系必须有来源和置信度 |
| FEATURE | 模型特征、训练快照、标签和时间边界 | 防止未来信息泄漏 |
| SERVING/ADS | API、地图、告警、报告、客户视图 | 必须有权限、版本和审计 |
| ARCHIVE | 不可变快照、备份、历史版本 | 定期恢复验证 |

## 5. 数据质量闸门

将现有 ODS 方案的 DQ1–DQ6 升格为全平台规则：

| 闸门 | 检查 | 默认动作 |
|---|---|---|
| DQ1 | 行数、分区和源端计数 | 不一致则阻断发布 |
| DQ2 | 主键/业务唯一键重复率 | 超阈值重跑或隔离 |
| DQ3 | 关键字段缺失与类型异常 | 生成字段可用性报告 |
| DQ4 | Join 覆盖率 | 不足时禁用该特征 |
| DQ5 | PSI、KS、分布和漂移 | 告警、冻结模型或降级 |
| DQ6 | 时间连续性和时区 | 补数或标记缺口 |
| DQ7 | 空间 CRS、范围和定位精度 | 无法确认则不得叠加分析 |
| DQ8 | 实体解析冲突 | 进入人工复核 |
| DQ9 | 许可证和用途 | 未批准则禁止出数 |
| DQ10 | 血缘、哈希、模型和报告版本 | 缺失则不可发布 |

现有 ODS 经验中，早期无 `ORDER BY` 的 OFFSET 分页造成大规模重复；因此全平台默认采用分区导出、keyset pagination、库内聚合、外部排序和 Parquet/Iceberg 快照，禁止手工不稳定分页。

## 6. 数据库组合建议

| 任务 | 首选 | 作用 |
|---|---|---|
| 本地分析和离线回测 | DuckDB + Parquet | 低运维、列式扫描、可复现 |
| 高速 DataFrame | Polars + Arrow | 向量化、低内存、跨语言交换 |
| 事务与空间查询 | PostgreSQL + PostGIS | 资产、实体、轨迹、空间索引 |
| 湖仓表管理 | Iceberg + 对象存储 | ACID、版本、time travel、schema evolution |
| 流式事件 | Kafka/Redpanda/Pulsar | 事件持久化、重放、实时消费 |
| 流式计算 | Flink/Spark Structured Streaming | 状态计算、窗口、流批融合 |
| 时序数据 | TimescaleDB/InfluxDB/QuestDB | 遥测、气象、设备和市场时序 |
| 全文检索 | OpenSearch/Elasticsearch | 文档、新闻、日志、事件搜索 |
| 关系图谱 | Neo4j/JanusGraph/RDF | 供应链、组织、资产和事件关系 |
| 空间服务 | GeoServer/MapLibre/Cesium | OGC 服务、二维/三维地图 |
| 元数据血缘 | DataHub/OpenMetadata + OpenLineage | 数据目录、血缘、影响分析 |

OpenLineage 将 dataset、job 和 run 作为可互操作的血缘核心对象；DataHub/OpenMetadata 可接收和展示这些血缘事件，适合把“谁生成了什么数据、由哪些输入变换而来”纳入平台审计。 [web:156][web:159][web:164]

## 7. 语义与本体

平台需要四种标识同时存在：

- **事实标识**：原始来源对象 ID。
- **规范实体标识**：统一的企业、港口、卫星、船舶、地点、事件 ID。
- **业务对象标识**：客户可理解的供应商、路线、资产、风险事件。
- **模型对象标识**：特征、标签、模型版本、评分和策略版本。

每条关系至少包括：

```text
subject_id
predicate
object_id
valid_from
valid_to
observed_at
source_id
source_locator
confidence
method
review_status
```

Palantir Ontology 的可借鉴之处不是复制闭源实现，而是让“对象、关系、动作、权限、模型和工作流”处在同一个可治理语义层。平台应以此思想把“供应商风险上升”“卫星可见窗口”“港口拥堵”“天气导致延误”变成可查询、可解释、可执行的业务对象，而不是孤立图表。

## 8. 量化与 AI 层

采用“规则先筛—模型排序—人工复核”的分层，不让一个大模型承担所有任务：

1. **规则层**：确定性、低延迟、可解释、可审计。
2. **统计层**：基线、置信区间、分布、异常和趋势。
3. **预测层**：分类、回归、生存、时序、图模型、视觉模型。
4. **因果层**：干预效果、异质性和反事实；不能把相关性当因果。
5. **情景层**：Monte Carlo、贝叶斯更新、情景树、敏感性和压力测试。
6. **语言/Agent 层**：只负责检索、摘要、字段映射、报告草稿和受控工具调用；关键事实必须回链原始证据。
7. **人审层**：高影响结果双人复核、申诉、回滚和复盘。

模型发布最低要求：

- 时间外测试。
- 空间外或行业外测试。
- 标签定义和观测窗口。
- 训练/验证/测试分割。
- 校准曲线和 Brier 分数。
- AUCPR、Recall@固定 FPR、C-index、MASE 等与业务场景匹配的指标。
- 漂移、偏差、失效样本和 kill switch。
- 特征快照、模型哈希、依赖清单和推理日志。

## 9. 时空与宇航模块

### GIS 与地球观测

- QGIS、GDAL、PROJ、GEOS、GRASS。
- PostGIS、GeoServer、MapLibre、deck.gl、CesiumJS。
- STAC、COG、Zarr、OGC API、WMS、WFS、WCS、WMTS。
- Sentinel-1/2、Copernicus Data Space、合法授权商业遥感、天气和地形资料。

### 宇航任务

- Orekit、GMAT、SPICE、Basilisk：开源/研究级轨道、姿态和几何分析。
- STK/ODTK：商业任务工程、覆盖、链路、定轨和任务排程。
- NASA cFS：cFE + OSAL + PSP 的飞行软件框架，不称为 OS。
- Cesium/3D Tiles：三维地球和轨迹展示。
- Meteomatics/公开气象：天气对发射、观测、能源、航运和基础设施的影响。

所有轨道计算应保存：星历来源、参考系、时间尺度、传播器、力模型、初始状态、协方差、软件版本和运行参数。

## 10. 安全与断网

### 控制平面

- 身份：OIDC/SAML、MFA、FIDO2、设备证书。
- 权限：RBAC + ABAC + purpose limitation。
- 密钥：KMS/HSM、信封加密、职责分离、轮换、吊销。
- 传输：TLS、必要时双向 TLS。
- 静态：数据库、对象存储、磁盘和备份加密。
- 供应链：SBOM、镜像签名、SLSA、Sigstore、依赖锁定。
- 审计：身份、数据、API、模型、KMS、备份和管理员操作日志。

### 断网平面

| 模式 | 能力 |
|---|---|
| Online | 全量接入、训练、汇总、API 和同步 |
| Intermittent | 本地缓存、延迟同步、优先级队列 |
| DDIL | 本地规则、离线地图、有限推理、store-and-forward |
| Air-gapped | 签名制品包、离线镜像、人工介质审批、双人授权 |
| Recovery | 哈希验证、冲突合并、差异报告、回滚和恢复演练 |

离线节点不得把过期天气、旧轨迹或旧事件伪装成实时数据；所有输出必须显示 `last_updated`、数据有效期、延迟和来源状态。

## 11. 业务定义与价值矩阵

| 业务域 | 决策问题 | 核心指标 | 可创造的价值 |
|---|---|---|---|
| 供应链 | 哪个节点可能中断 | 暴露度、集中度、替代天数、事件提前量 | 降低停产和库存风险 |
| 港口物流 | 哪里会延误 | 拥堵、停留、天气暴露、ETA 误差 | 减少滞期、燃料和人工成本 |
| 商业航天 | 何时/何地可观测或通信 | 覆盖率、可见窗口、链路可用率 | 提升任务利用率和保险定价 |
| 农业 | 何时灌溉、收获或防灾 | 降水概率、土壤湿度、植被指数 | 减少损失、提高产量 |
| 能源 | 发电和负荷如何波动 | 风/光预测、温度、爬坡、偏差 | 减少平衡成本和弃电 |
| 地缘 | 哪些事件改变业务环境 | 事件强度、政策方向、传播速度 | 提高投资和运营决策提前量 |
| 合规 | 数据和模型是否可审计 | 血缘、权限、异常访问、恢复成功率 | 降低处罚和审计成本 |
| 运营风控 | 哪些行为需人工复核 | 命中率、误报率、复核时间 | 降低损失，同时避免误伤 |
| 研究咨询 | 哪些结论可被证明 | 来源覆盖、外样本、敏感性 | 提高报告可信度和续约率 |
| 平台服务 | 客户是否持续获得价值 | 使用率、API 调用、留存、毛利 | 构建经常性收入 |

## 12. 最高效率设计

效率不是单纯追求最快，而是：

\[
	ext{总效率} = rac{	ext{可验证业务价值}}{	ext{计算成本} + 	ext{数据成本} + 	ext{维护成本} + 	ext{风险成本}}
\]

建议采用：

- 原始数据只保存一次，派生层不复制无意义宽表。
- Parquet/Iceberg 分区按业务日期、空间网格和数据域设计，不按随机批次设计。
- 先聚合、后下载；先筛选、后重算；先样本、后全量。
- DuckDB/Polars 处理本地和中型数据，Spark/Flink 只在并行规模确实需要时启用。
- 热数据、温数据、冷数据分层存储。
- 对同一实体只建立一个规范 ID，并保存别名和匹配证据。
- 将计算结果缓存，但保留输入快照和重算路径。
- 对模型和 API 设预算、限流、缓存、超时和降级策略。
- 以可观察性追踪数据延迟、失败率、查询耗时、成本和客户使用，而不是只看 CPU 利用率。

## 13. 商业化产品路线

第一优先级：**供应链地缘风险雷达**。

第二优先级：**商业航天与地球观测分析服务**。

第三优先级：**天气—能源—物流预测**。

第四优先级：**断网优先私有 GIS 与证据平台**。

第五优先级：**数据质量、模型治理和 Quarto 证据报告服务**。

收费组合：

- 一次性数据工程和接入费。
- 月/年订阅。
- API 调用费或实体数量费。
- 私有化部署费。
- 维护、SLA、模型监控和安全审计费。
- 定制报告和顾问日费。
- 培训、数据字典和客户团队认证。

## 14. 建议的最小可行平台

```text
MinIO/S3
+ Parquet/Iceberg
+ DuckDB/Polars/Arrow
+ PostgreSQL/PostGIS
+ Kafka（必要时）
+ Python/R/SQL
+ QGIS/GeoServer/CesiumJS
+ Neo4j 或 RDF
+ MLflow/DVC/Evidently
+ DataHub/OpenMetadata/OpenLineage
+ Keycloak/Vault
+ Quarto
```

第一阶段不建议一开始就使用全部 Spark、Flink、Kubernetes、图数据库和大模型。先用单机/小型私有集群完成一条真实客户链路，只有当数据量、并发、延迟或隔离要求证明必要时再升级。

## 15. 90 日行动计划

| 阶段 | 任务 | 结果 |
|---|---|---|
| 1–2 周 | 数据资产、许可证、客户和业务定义 | 产品边界与可用数据清单 |
| 3–4 周 | RAW/BRONZE/SILVER/GOLD、血缘和 DQ | 可重跑数据管线 |
| 5–6 周 | PostGIS、DuckDB、Parquet、实体解析 | 可查询时空和关系底座 |

## 16. 终极验收标准

平台只有同时满足以下条件，才称得上“十项全能”：

- 每条业务结论都有来源和版本。
- 每份数据都知道许可和用途限制。
- 每个模型都知道训练边界、外样本表现和失效条件。
- 每个空间对象都有 CRS、精度和有效时间。
- 每个实体关系都有匹配证据和置信度。
- 每次转换都能通过血缘重现。
- 每个高影响输出都有人工复核和回滚。
- 断网时仍能执行限定功能且不伪造实时状态。
- 恢复时能证明数据完整、无重复、无冲突遗漏。
- 客户价值能以节省、止损、提前量、准确率、续费率或毛利衡量。
