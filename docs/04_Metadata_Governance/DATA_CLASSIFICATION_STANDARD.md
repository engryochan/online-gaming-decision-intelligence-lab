# 数据分类标准

## 1. 目的

本文件用于定义在线游戏决策智能实验室（OGDIL）范围内数据表、字段、注释及衍生资产的分类规则，为访问控制、脱敏策略以及仓库公开与否的决策提供依据。

## 2. 分类对象

分类适用于以下对象：

- 数据库、数据表（ODS / DWD / DWS / ADS 各层）
- 字段及字段业务注释（`COLUMN_COMMENT`）
- 数据字典、Schema 导出文件（如 information_schema 快照）
- 特征（Feature Store）及模型输出
- 报表、仪表盘与实验结果

## 3. 分类等级

| 等级 | 名称 | 定义 | 典型处理方式 |
|------|------|------|----------------|
| L0 | 公开 | 可对外公开，不含业务敏感信息 | 可进入公开仓库 |
| L1 | 内部 | 仅限团队/公司内部使用 | 私有仓库，禁止外发 |
| L2 | 机密 | 涉及具体业务规则、运营策略或财务逻辑 | 私有仓库并限制访问权限 |
| L3 | 受限 | 涉及可识别个人的信息或强监管数据 | 禁止导出，仅授权环境可访问 |

## 4. 分类判定原则

- 表结构（表名、字段名、数据类型）本身通常判定为 **L1**；
- 字段业务注释若揭示具体运营规则（如活动机制、代理层级、资金处理逻辑），判定为 **L2**；
- 涉及用户身份、联系方式、账号、交易明细等可识别个人信息的字段，判定为 **L3**；
- 同一张表内不同字段可以有不同分类等级，最终该表的对外披露等级取其中**最高**的字段等级。

## 5. ODS 层专项要求

ODS 层数据字典（如 `01_ODS_TABLE_LIST.csv`、`02_ODS_FULL_DATA_DICTIONARY.csv`）直接来源于生产数据库的 information_schema 导出，字段注释可能包含具体业务逻辑说明。此类文件在纳入版本控制或对外发布前，必须完成以下步骤：

1. 按照第 4 节判定每个字段的分类等级；
2. 对 L2 / L3 字段的 `COLUMN_COMMENT` 进行脱敏或删除处理，仅保留数据类型与是否可空等结构性信息；
3. 若整份数据字典中 L2 / L3 字段占比较高，应评估是否将该文件整体移出公开仓库，改为私有仓库或子模块管理；
4. `.gitignore` 中如存在数据文件的排除规则（如 `*.csv`），任何以 `git add -f` 方式强制加入版本控制的例外情况，必须在 Pull Request 描述中说明理由，并经至少一名评审确认分类等级。

## 6. 实施流程

1. 数据接入 ODS 层时，由数据负责人（Data Owner）完成初始分类；
2. 分类结果记录在元数据目录（`metadata/classification/`）中；
3. 分类等级变更须遵循《元数据变更策略》（`METADATA_CHANGE_POLICY.md`）中定义的流程；
4. 分类结果每季度复审一次，或在数据源结构发生重大变化时触发复审。

## 7. 与其他规范的关系

- 分类结果是《数据质量标准》中差异化质量要求的输入之一；
- 分类结果决定《数据血缘标准》中血缘信息的可见范围；
- 分类变更须同步更新至《元数据治理框架》所定义的治理台账。
