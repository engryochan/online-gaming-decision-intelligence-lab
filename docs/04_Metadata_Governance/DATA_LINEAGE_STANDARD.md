# 数据血缘标准

## 1. 目的

本文件定义在线游戏决策智能实验室（OGDIL）数据血缘（Data Lineage）的记录范围、记录粒度与维护方式，确保 ODS → DWD → DWS → ADS 全链路的数据流转可追溯、可解释。

## 2. 血缘管理对象

血缘记录覆盖以下链路上的每一次数据流转：

```
源系统（业务数据库）
    ↓
ODS（真相层）
    ↓
DWD（明细数据仓库）
    ↓
DWS（汇总数据仓库）
    ↓
ADS（应用数据服务）
    ↓
特征存储 / 模型 / 仪表盘 / 决策平台
```

对每一次流转，血缘信息至少应记录：来源对象、目标对象、转换逻辑（SQL / 脚本引用）、负责人、更新时间。

## 3. 血缘记录粒度

- **表级血缘**：记录源表与目标表之间的依赖关系，为默认最低要求，所有 ODS→DWD→DWS→ADS 的流转均须具备表级血缘；
- **字段级血缘**：记录目标字段由哪些源字段、经过何种转换逻辑计算得出，ADS 层核心指标字段（尤其是用于对外报表或模型特征的字段）应优先补全字段级血缘。

## 4. 血缘记录方式

- 优先通过静态解析 `sql/` 目录下的 ETL 脚本自动生成血缘关系，避免人工登记与实际代码不一致；
- 暂不具备自动化解析能力的阶段，允许通过 `metadata/lineage/` 下的清单文件手工登记，但须在自动化工具落地后完成迁移；
- 血缘记录必须与对应的 Git 提交关联，便于回溯某一版本血缘对应的具体代码状态。

## 5. 血缘与数据契约的关系

每张 ADS 表的数据契约（Data Contract）中，"来源"字段必须与血缘记录保持一致；数据契约变更（如更换上游依赖）必须同步触发血缘信息更新，二者不得脱节。

## 6. 血缘变更触发条件

以下情形必须更新血缘记录：

- 新增或下线某一层级的表；
- ETL 脚本中调整了字段的来源或转换逻辑；
- 上游源系统（如 `ods_mariadb_2b` 等 schema）发生变更；
- 数据分类等级（参见《数据分类标准》）发生调整，可能影响血缘信息的可见范围。

## 7. 血缘的可见范围

血缘记录本身可能间接暴露业务逻辑，其可见范围应参照来源表与目标表中**较高**的数据分类等级执行；面向公开仓库展示的血缘图，应仅保留表级关系，隐去涉及 L2 / L3 字段的转换细节。

## 8. 血缘可视化与查询

后续版本计划提供基于 `metadata/lineage/` 数据自动生成的血缘图（Mermaid 或专用血缘工具），供研究人员在开发新特征或模型前，快速评估上游依赖范围与变更影响面。
