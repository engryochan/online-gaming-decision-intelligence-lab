# 数据质量标准

## 1. 目的

本文件定义在线游戏决策智能实验室（OGDIL）数据质量的评估维度、分层要求与问题响应机制，保障进入 ADS 层供分析、AI 与仪表盘使用的数据是可信的。

## 2. 数据质量六大维度

| 维度 | 说明 |
|------|------|
| 完整性（Completeness） | 必填字段是否缺失、记录数是否与源系统一致 |
| 准确性（Accuracy） | 字段值是否真实反映业务事实 |
| 一致性（Consistency） | 同一实体在不同表 / 不同层之间的取值是否矛盾 |
| 及时性（Timeliness） | 数据同步与刷新是否满足既定频率 |
| 唯一性（Uniqueness） | 主键 / 唯一键是否存在重复 |
| 有效性（Validity） | 字段值是否符合预定义的取值范围、格式或业务规则 |

## 3. 分层质量要求

- **ODS 层**：以「不失真」为核心，重点检查同步是否完整（记录数比对）、`__source_pk` 是否唯一、`dt` 分区是否连续；不在此层做业务逻辑修正。
- **DWD 层**：在保留明细的基础上，开始执行格式标准化、异常值标记与基础一致性校验。
- **DWS 层**：重点校验聚合口径是否与业务定义一致，同一指标在不同汇总表之间不得出现口径冲突。
- **ADS 层**：质量要求最高，须满足完整的数据契约（Data Contract），并在对外提供服务前完成全部六大维度的检查。

## 4. 质量规则类型

- **硬规则（Blocking）**：违反即阻断下游任务运行，例如主键重复、必填字段为空；
- **软规则（Warning）**：违反不阻断流程，但生成告警并记录，供人工复核，例如数值超出历史波动范围。

## 5. 质量检查触发时机

- 每次 ETL 任务执行后自动运行；
- 数据字典或 Schema 发生版本变更时（参见《ODS 数据模式版本管理规范》）；
- 数据契约变更时；
- 按周期（建议每日）对 ADS 层核心表执行全量质量扫描。

## 6. 质量问题分级与响应

| 级别 | 定义 | 响应时限 |
|------|------|----------|
| P0 | 阻断下游分析或生产决策 | 立即处理 |
| P1 | 影响部分指标准确性，暂无阻断风险 | 1 个工作日内处理 |
| P2 | 轻微异常，不影响核心结论 | 纳入下一迭代处理 |

## 7. 质量报告

质量检查结果统一记录在 `metadata/quality/` 下，按表、按日期归档；ADS 层核心表的质量报告应在数据契约文档中提供可追溯链接。

## 8. 与其他规范的关系

数据质量检查的字段范围与告警可见性，需参照《数据分类标准》确定的等级执行；质量问题导致的结构性修复须遵循《元数据变更策略》中定义的变更流程。
